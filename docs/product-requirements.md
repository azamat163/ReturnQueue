# Return Queue: требования и объём первого прототипа

Дата: 3 октября 2026 года. Решение пользователя: бесплатное iPhone-приложение;
сначала проверить пользу, монетизацию отложить. Ниша остаётся гипотезой.

## Для кого и зачем

Для американского покупателя, который одновременно возвращает покупки из нескольких
магазинов. Задача: быстро сохранить вещи, собрать их по месту сдачи, отметить сдачу
и довести дело до понятного итога. Магазин покупки и точка сдачи — разные поля.

Приложение ничего не проводит через банк и не гарантирует возврат. Пользователь сам
вводит условия покупки и подтверждает поступления. Интерфейс — английский, суммы — USD.

## Первый прототип P1

| Сценарий | Что должно работать |
|---|---|
| Добавить возврат | Только вещь и магазин обязательны; неизвестные дата, сумма и место допустимы |
| Собрать поездку | Группы по месту сдачи, ближайшие сроки, отдельная группа неизвестного места |
| Отметить сдачу | Перенос из To return в Waiting for refund с собственной датой события |
| Записать возмещение | Несколько ручных поступлений; деньги отдельно от магазинного кредита |
| Завершить дело | Полный/частичный итог, отказ, отмена или решение оставить вещь |
| Исправить ошибку | Изменить поля/статус без молчаливой потери истории |
| Сохранить контроль | Удаление с подтверждением, экспорт, preview и восстановление архива |

В навигации доступны To return, Waiting for refund и History; данные хранятся локально.
Нет сложного onboarding, регистрации, карты, paywall, рекламы или обращения в магазин.

## Следующий бесплатный этап P2

Один снимок чека/подтверждения и полный перенос фото с архивом; необязательные локальные
напоминания без личных деталей на экране блокировки. Отказ в разрешениях не мешает журналу.
Не добавлять OCR, подключение почты/банка, сервер и автооформление возврата.

## Основные случаи, которые нельзя пропустить

- Нет известного срока — нет придуманного дедлайна.
- Срок прошёл — не объявлять отказ магазина.
- $50 деньгами + $50 кредита — денежный итог $50.
- При ожидании $100 получено $80 — можно закрыть с явным частичным итогом и разницей.
- Неизвестная ожидаемая сумма — не вычислять полноту или остаток.
- Смена часового пояса — не сдвигает календарную дату.
- Повреждённые данные — не заменяются пустым списком.
- Плохой архив — не меняет нынешние записи; повторный restore не создаёт дубликаты.

## Как проверим пользу

После рабочей сборки провести небольшой 14-дневный тест: могут ли пять пользователей
быстро сохранить запись, пройти возврат без помощи и повторить использование на новой
покупке. Отдельно фиксировать, возник ли у человека новый возврат: отсутствие повода
для повторения не равно отказу от продукта. Проверка оплаты сейчас не нужна.
