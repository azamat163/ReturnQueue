# Решения планирования

Дата: 2026-10-03. Входы: пользовательские сообщения, три аудита сабагентов,
[спецификация](spec.md), локальная проверка среды. Это решения проекта, а не рыночные факты.

| Решение | Причина | Альтернатива |
|---|---|---|
| Бесплатный прототип | Явное указание пользователя | Монетизация и цена отложены |
| Необязательные срок/сумма/место | Можно быстро сохранить неполную запись | Обязательные поля приводят к выдуманным датам |
| Группировка по месту сдачи P1 | Это центральная гипотеза удобства | Только список сроков слабо проверяет идею |
| Отдельные события cash/store credit | Несколько поступлений и частичная компенсация | Одно число теряет историю и смешивает деньги с кредитом |
| Ручное закрытие с итогом | Полная цена не всегда возвращается | Автозакрытие по равенству суммы недостоверно |
| Backup с заменой и preview | Однозначное восстановление без конфликтов | Merge создаёт отдельный конфликтный workflow |
| Gregorian calendar day | Выбранный день не меняется при путешествии | UTC timestamp может отображаться другой датой |
| SwiftUI + pure Swift core | iPhone выбран; ядро проверяется без UI | Веб-продукт не выбран пользователем |
| Фото/напоминания P2 | Сначала проверить основной процесс | Всё одновременно увеличивает первый объём |

Разрешённые расхождения рекомендаций:
UX-аудит считал дату обязательной и grouping P2; выбраны неизвестная дата и grouping P1.
Аудит ядра предлагал закрытие только при равенстве ожидания; выбран ручной итог с разницей.
Правила этих решений закреплены в FR-006, FR-008, FR-020/021.

Среда: доступны Swift и CLI, нет полноценного Xcode. Требования сформированы,
проверка iOS-экрана отложена до наличия среды, бизнес не объявлен валидированным.
